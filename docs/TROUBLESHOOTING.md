# 排错

## 第一步：看日志

```
sd:/switch/cloud-sync/logs/sync.log
```

图形界面里的进度页会显示最近日志，完整内容在文件里（超过 1 MB 自动轮转）。

---

## 界面相关

### 启动后没有文字 / 只有色块

系统共享字体初始化失败。看日志里的：

```
Fonts: N faces loaded
字体初始化失败: ...
plInitialize failed (0x...)
```

常见原因：

- 运行环境异常（重启一次 Switch）
- 使用了被修改过的系统固件，`pl:u` 不可用

没有字体时界面无法显示文字，请把日志发出来。

### 系统键盘打不开

`swkbd` 在 applet 模式下偶发失败。退出应用重进一次，或改用全内存模式（按住 `R` 进 hbmenu）。

### 界面卡顿

相册很多时首屏仍在用软件渲染，属于正常。减少一次性显示的内容不影响功能。

## 存档相关

### `fsOpenSaveDataFileSystem 0x...` / 「无法挂载」

最常见原因：**该游戏正在运行**，存档被系统占用。

处理：HOME → `X` → Close 完全关闭游戏，再上传/恢复。

### 「跳过（未变化）」

正常。说明这个存档的 `commit_id` 或 SHA-256 和上次一致，没有上传。

### 「跳过：超过上限」

单个存档归档超过设置里的 MB 上限，调大上限或检查是不是异常大的存档。

### 恢复后游戏里没有进度

- 游戏必须在恢复**之后**启动
- 看日志里是否出现 `archive OK`、`restored N files`
- 检查 `校验失败`：说明服务器上的文件和服务端列表里的 SHA-256 不一致，通常是服务端写入不原子

### 「本地没有对应的存档」

服务器上有这份存档，但本机没有安装该游戏，或当前用户不匹配（`user_id` 不同）。

## 网络 / HTTP

| 现象 | 处理 |
| --- | --- |
| `curl 6` / `curl 7` | DNS 或连接失败：检查网络、地址、端口、防火墙 |
| `curl 28` | 超时：调大「网络超时」，或检查服务器/带宽 |
| `curl 55` | 服务端提前断开：检查反向代理的请求体大小限制 |
| `curl 60` | TLS 证书校验失败：放 `ca-bundle.pem`，或内网临时跳过校验 |
| `HTTP 401 / 403` | 令牌错误，或 token 与 device 不匹配 |
| `HTTP 404` | `base_url` 路径不对，或服务端没实现该端点 |
| `HTTP 413` | 超过服务端限制 |
| `HTTP 500` | 服务端错误：看服务端日志（磁盘满、权限、临时目录） |

`HTTP 200` 但仍失败时，看响应体里的 `message=`。

## 游玩记录相关

### 只上传了汇总，没有详细事件

检查设置里的「详细游玩事件」是否开启（`[playtime] detailed = 1`），以及日志里是否有：

```
Play log: N events read
```

### 事件数量比 NX-Activity-Log 少

系统 Play Log 是环形缓冲，旧事件会被覆盖。本应用和 NX-Activity-Log 读取的是同一份数据，但：

- 只统计 `play_log_policy == All` 的记录
- 只包含有账号登录事件的会话
- 只保留 `applet_id == Application` 且标题 ID 属于游戏的情况

### 同一游戏出现两个用户

正常：Switch 允许不同用户分别游玩，记录按「标题 × 用户」分开。

## 相册相关

- 只上传 `jpg / jpeg / mp4`
- 判断依据：相对路径 + 文件大小 + 修改时间
- 默认**不删除**本地文件（`album.delete_after_upload = 0`）
- 如果日志显示 `ImageDirectory 挂载失败`，会自动回退到 `sdmc:/Nintendo/Album`

---

## 设备 ID

- 自动生成的 ID 保存在 `state/device_id.txt`
- 换了 ID 服务器会当成新设备
- 想固定：设置在「设备 ID」里填一个值并保存

---

## 恢复存档前务必确认

1. 游戏已完全关闭
2. 服务端保留了历史版本
3. 选中了正确的时间点（列表显示 UTC）
4. 恢复失败后不要启动游戏，重新恢复；必要时用历史版本再试
